Unicode и терминальные ширины

В версии 0.1 используется детерминированный консервативный профиль без внешних Go-зависимостей. Проверены кириллица/латиница, широкие CJK, combining marks, variation selectors, emoji modifiers, ZWJ-emoji и пары региональных индикаторов. Широкий кластер не записывается наполовину на правой границе. При перезаписи canvas удаляется целиком прежний wide glyph и его continuation cell.

Это не полная реализация Unicode UAX #29 и не гарантия одинаковой ширины каждого emoji/сложного письменного кластера во всех терминалах. Indic conjuncts, Hangul jamo composition и другие сложные границы требуют отдельной проверки. East Asian Ambiguous здесь имеет ширину 1. Шрифт, конфигурация terminal emulator и multiplexer могут выбрать иной профиль. Для неподтверждённых последовательностей передайте проверенные текстовые labels в host-adapter; не считайте byte length шириной строки.

ASCII-режим заменяет только технические символы рамок/стрелок/sparkline. Текст пользователя остаётся Unicode; режим не заявлен как универсальная защита от несовместимой ширины emoji.

C0/C1, ESC/OSC и управляющие bidi override/isolate не проходят в текстовый кадр. Удалённый ESC может оставить видимую строку вроде [31m; это текст, не терминальная команда. Только сериализатор цветов SDK создаёт SGR-последовательности. Цветовые роли с неизвестным именем получают безопасный fallback.

Начальные отдельные combining marks получают dotted-circle base. Табуляция при однострочной отрисовке превращается в один пробел; многострочный text делится по LF до отрисовки.

Ограничения фиксируются явно, чтобы ранний SDK не выдавался за полностью Unicode-конформный терминальный backend. Основные проверяемые инварианты: отсутствие terminal-control injection, ограниченная геометрия, сохранение поддерживаемого wide/combining cluster и одинаковая раскладка во всех темах.
