# Источники и границы переноса

## ultra-mog: только идея графиков, не оформление

Проверен `Sacraer-group/ultra-mog`, commit:
`7975feefe2e3530cd026ec99dfe6d862a6e9e02f`.

- [src/pixels.rs](https://github.com/Sacraer-group/ultra-mog/blob/7975feefe2e3530cd026ec99dfe6d862a6e9e02f/src/pixels.rs)
  — `raster`, `line`, `put`: ограниченный RGB-растер, Bresenham, дополнительный пиксель по Y,
  сетка на ¼, ½, ¾, адаптивная ширина пикселей относительно клетки; `can_draw`/MAX_PIXELS.
- [src/ui.rs](https://github.com/Sacraer-group/ultra-mog/blob/7975feefe2e3530cd026ec99dfe6d862a6e9e02f/src/ui.rs)
  — `graph_segments` (район строки 2807), `draw_chart_segments`, `draw_network_chart`,
  `device_trend`, `usage_bar`: разрывы данных/времени, фиксированные оси, несколько рядов,
  Octant/ASCII marker, восьмиуровневые sparkline и процентные бары.
- [LICENSE](https://github.com/Sacraer-group/ultra-mog/blob/7975feefe2e3530cd026ec99dfe6d862a6e9e02f/LICENSE)
  — MIT, copyright (c) 2026 Sacraer-group. Полный notice приложен.

Это JavaScript-адаптация принципов/вычислений, а не буквальная сборка Rust-приложения.
Код Ratatui не включён и не выполняется. Сравнение с нативным pixel-perfect снимком не проводилось.

### Что сохранено

Временные окна, разделение непрерывных участков, >20s как временной разрыв, нулевой baseline,
целочисленная линия, bounded raster, восемь sparkline-уровней и три семейства renderer.

### Что изменено намеренно

- RGB цвета передаются только из ролей активной темы SACRA TUI, включая цвет сетки. Формула осветления background
  из ultra-mog не используется, чтобы не вводить дополнительные цветовые токены.
- Canvas RGBA вместо Kitty escape-последовательностей, zlib и terminal placements.
- Octant рисуется bitmap-геометрией 2×4, не Unicode Octant из локального шрифта.
- ASCII-серия 2 обозначена `+` для различимости; в источнике ASCII marker — `*`.
- Добавлены браузерный курсор, выгрузка JSON/TXT и переключатель искусственных пропусков.
- Raster проецирует/ограничивает значения до области графика. Подпиксельный phase-shift и
  терминальный цикл плавной прокрутки источника не воспроизводятся.
- Интервал demo-данных 1s; непрерывного animation loop не требуется.

## SACRA: палитра и общая семантика

[site/tokens.json](https://github.com/Sacraer-group/sacra-ui-kit/blob/b511607340bcf315aa632c40dfc4328a344e2c92/site/tokens.json)
из `sacra-ui-kit` — все 17 `--s-color-*`. Палитра ultra-mog не переносилась.
Моноширинный local-first подход, yellow focus / green success / red error продолжают SACRA.

## Спроектировано для этого архива

Стартовый каталог компонентов, компоновка из пяти экранов, правила клеточных отступов, TUI-версии форм, системные состояния,
командная палитра, demo-задачи/инспектор и план будущего `tui/`-слоя.
Синтетическая модель данных никак не описывает реальную машину пользователя.

## Не реализовано / не утверждается

Нет нативного TUI, PTY, ANSI parser, Kitty protocol negotiation, полного wcwidth/grapheme layout,
универсальной поддержки всех терминалов, реальных файловых/системных действий и backend API.
Оформление ultra-mog (включая компоновку, заголовки, рамки и навигацию) не служит образцом для SACRA.
Не импортированы palette/theme loaders и системные collectors из ultra-mog.
Шрифты не включены. GitHub-репозитории в этой задаче только читались.


## Координатная рамка: изображение пользователя

В 0.2 добавлены пунктирный периметр, центральное перекрестие, риски по сторонам и кресты
на углах по предоставленному изображению каркасной формы. Сама форма/сетка поверхности
не копируется в графики. Декоративная рамка превращена в настоящую координатную систему:
метки и курсор рассчитываются по данным, ноль не переносится автоматически в центр.
SVG-рамка, адаптивные метки и управление курсором написаны для этого прототипа.

## Палитры btop

Использованы только семейства цветовых палитр. Компоненты, рамки, компоновка и семантика
остаются SACRA; исходные `.theme` и код btop в архив не включены. Таблица источников,
авторов исходных палитр и границы адаптации — в [THEMES.md](THEMES.md).
