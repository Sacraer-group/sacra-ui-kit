# SACRA / TUI — дизайн отдельного терминального слоя

Статус: предложение 0.2. Браузерная симуляция служит исполняемым визуальным референсом.
Это не перенос веб-CSS в терминал и не обещание одинакового рендера во всех терминалах.

## 1. Место в системе

SACRA сохраняет две формы одного языка: веб `site/` и будущий терминальный `tui/`.
Общие: семантика цветов, имена состояний, контент и принципы навигации.
**ultra-mog не является референсом оформления:** только идея графических режимов, дискретных линий и обработки отсутствующих данных. Все экраны, компоненты, навигация и правила здесь — отдельный дизайн SACRA.
Различаются: единицы компоновки, геометрия компонентов, обработка клавиш и механизм вывода.

Предлагаемая структура после согласования (в этой задаче ничего не коммитилось):

```text
index.html                        существующая веб-витрина
site/                             существующий веб-набор, без замены
skills/                           существующие навыки
tui/
  index.html                      эта браузерная лаборатория
  assets/                         симуляция и токены
  examples/                       компоновка и контракты
  docs/                           правила TUI-слоя
  tests/                          проверки геометрии и поведения
```

Нативный backend добавляется лишь при первой реальной TUI-задаче. До этого не нужны отдельная
библиотека, менеджер плагинов, сборщик темы или пять непроверенных адаптеров.
Для будущего агента достаточно отдельной инструкции: выбирать TUI-референсы для терминальных
задач, а не превращать обычные web-компоненты в псевдотерминал. Установку навыков этот архив не меняет.

## 2. Геометрия: клетка вместо пикселя

Основная единица — знакоместо по X и строка по Y. В браузерном макете это `1ch` и `20px`
при шрифте 12px. Это **модель клетки**, а не определение физического размера клетки в терминале.

| Элемент | Терминальная спецификация |
|---|---|
| Внешняя рамка | 1 клетка, прямые углы, без тени |
| Внутреннее поле | 1 строка сверху, 1–2 клетки по горизонтали |
| Промежуток между панелями | 2 клетки / 1 строка |
| Заголовок панели | 1 строка, подпись в разрыве рамки |
| Строка таблицы | 1 строка; метаданные только при достаточной высоте |
| Командная строка | 1 строка + видимый признак режима |
| Статусная строка | Прижата вниз; не прокручивается вместе с контентом |
| Скругления, размытие, тени | Нет |

Браузер использует тонкие CSS-рамки, DOM-таблицы и контейнерные брейкпоинты как визуальную
аппроксимацию. Нативный renderer должен выводить рамки символами и раскладывать данные по
реальной сетке терминала. Высота каталога в браузере может расти; в нативном клиенте контент
должен иметь внутренний скролл, а верхняя и нижняя строки — оставаться на месте.

Порог определяется шириной **контентной области**, а не окна браузера:

- больше 132 клеток: левая навигация + центр + правый инспектор;
- 97–132: центр + инспектор; постоянная левая навигация скрыта;
- 65–96: одна основная колонка, вторичные панели ниже;
- 64 и меньше: компактный режим превью. Для настоящей TUI на очень узком терминале лучше
  показывать один экран/инспектор за раз, а не уменьшать размер шрифта.

Числа выравниваются вправо, имена — влево. Ширина определяется терминальными колонками,
не длиной UTF-8 в байтах. В нативной реализации обязательна проверка широких CJK,
комбинируемых символов и обрезки без разрыва графемы. Здесь произвольные такие строки не моделируются.

## 3. Палитры: одна семантика, восемь вариантов

Все 17 исходных цветовых токенов SACRA 1.4.3 остаются в `assets/tokens.css` без изменений.
По умолчанию применяется SACRA Graphite. Семь альтернатив находятся в `assets/themes.js`
и `themes.json`: Nord, Gruvbox Dark, Dracula, Tokyo Night, Solarized Dark, Solarized Light, Mono Graphite.
Терминальный слой не наследует встроенные темы ultra-mog; компоновка не зависит от палитры.
Цветовые семьи btop переосмыслены через роли SACRA, с собственными оттенками для читаемости.
Применение ограничено корнями TUI/диалогов/уведомления; внешняя обложка не меняется.
Подробнее — `THEMES.md`. Следующая таблица описывает тему по умолчанию.

| Роль | Токен | Использование |
|---|---|---|
| Холст | `canvas` · #15191F | основной фон |
| Панель | `surface` · #1B2027 | отделение групп |
| Поднятый слой | `raised` · #222831 | header, status, меню |
| Вложенный слой | `sunken` · #11151A | input/code; не весь экран |
| Навигация | `accent` · #F2CC4D | фокус, текущая вкладка, основной ряд графика |
| Успех | `success` · #45BF92 | подтверждённое действие + [OK] |
| Ошибка | `danger` · #EF7B6D | ошибка + текст причины |
| Служебный текст | `muted` / `subtle` | подписи и второстепенные данные |

Графики: первый ряд — accent, второй — text активной палитры (жёлтый/светлый в SACRA). Для ASCII второй ряд дополнительно
помечен `+`. Цвет не заменяет легенду, единицу и шкалу. Нет градиентов, свечения и радужных
рядов. У всех палитр общая семантика ролей, а не случайная окраска отдельных виджетов. Mono Graphite меняет цвета на градации серого; это не нативный monochrome/256-color backend.
Терминальная деградация по capability остаётся будущей задачей.

## 4. Типографика и символы

Один локальный моноширинный стек: Liga SFMono Nerd Font → SF Mono → Menlo → monospace.
Файлы шрифтов не поставляются. Функциональность не требует Nerd-глифов.
Иконки — короткие текстовые метки, рамки, стрелки и [OK]/[ERR]/[N/A].

Крупный editorial-заголовок есть только у браузерной обложки. Внутри терминального макета
текст имеет один кегль. Иерархия строится на контрасте, пустой строке, служебных метках и
группировке, а не на произвольном CSS font-size.

Терминальная графика допускает исключение: Pixels использует bitmap, Octant — восемь
субклеток. Текстовые подписи всё равно остаются в сетке. ASCII-переключатель прототипа
меняет **графики**, а не превращает весь интерфейс в семибитный ASCII.

## 5. Разделение состояний

`focus` — куда попадёт клавиатурное действие. `selected` — какая запись открыта.
`checked` — значение независимого переключателя. Это разные состояния.

- Focus: контур/рамка акцентом темы (жёлтый по умолчанию), виден при Tab.
- Selected: акцентная метка `›` и слабая заливка строки. Не исчезает при уходе фокуса.
- Checked: `[×]`, не заливка всей строки; radio — `(•)`.
- Disabled: приглушённый элемент без обработчика действия; причина рядом, когда она нужна.
- Pending: запрет повторного запуска только на время операции.
- Success: подтверждение цветом success **после** успешной операции.
- Error: код/метка + понятное действие; не одна красная рамка.
- Missing: `N/A` или `—` и причина, не ноль.
- Stale: последняя известная величина с возрастом. В прототипе не эмулируется, но в native
  контракте должна отличаться от missing.

## 6. Клавиатура

В браузере Tab остаётся стандартным — пользователь всегда может покинуть симуляцию.
Горячие клавиши включаются внутри терминального макета; ввод текста имеет приоритет.

`1–5` — компоненты / задачи / графики / монитор / правила; `j/k`, стрелки — строки; `/` — поиск; `s` — сортировка; `:` — команды;
`p` — пауза; `w` — окно; `t` — палитры; `g` — сетка; `?` — справка; `v` — только TUI. На графике стрелки управляют курсором.

Режимы: Normal → Input → Normal, Normal → Confirm → Normal. Esc возвращается ровно на
один уровень. Dialog держит фокус средствами `<dialog>`. Для потенциально опасного действия
первоначально выбран безопасный выход «Отмена»; подтверждение требует перехода на действие.
В браузере не перехватываются Cmd/Ctrl/Alt-комбинации. Нативные горячие клавиши следует
проектировать отдельно с учётом терминала, tmux и оболочки.

## 7. Графики

Из ultra-mog берём способы отрисовки, а не расположение всего интерфейса и не цвета.
Точные исходные функции и изменения перечислены в `SOURCES.md`.

- История режется на сегменты при null/NaN/Infinity и разрыве времени более 20 секунд.
- 0 — полноценный sample на baseline. Никакой имитации «нет данных» через нулевую кривую.
- Временное окно 1 / 5 / 15 минут. Метки отражают выбранное окно.
- CPU/GPU: шкала 0–100%; RAM: 0–16 GiB в этом **демо**; обе сетевые серии: общая шкала.
- Общая рамка: пунктирный периметр, кресты по углам, большие/малые деления и центральное
  перекрестие по референсу пользователя. Независимый SVG-слой в браузере, не часть растра данных.
- Метки осей вычисляются из тех же bounds/window, что и ряды. По X отображается реальное
  время относительно последнего sample: например −5m / −3:45 / −2:30 / −1:15 / now.
- Центр сетки — середина диапазона, не всегда математический ноль. Для [0,100] ноль внизу;
  для диапазона с отрицательными значениями `TuiCoordinates` вычисляет отдельную линию Y=0.
- На узкой области меньше подписей. Диапазон остаётся прежним, кегль не уменьшается.
- `g` скрывает внутренние направляющие и риски; внешний периметр и числовые оси остаются.
- Курсор показывает вертикальную + горизонтальную направляющие и точку ближайшего sample.
  На null нет горизонтальной линии/точки. На сетевом графике текст readout показывает обе серии.
  Клавиатурный шаг — 1s независимо от выбранного временного окна.
- Raster: Bresenham без сплайнов, прозрачный фон над общей координатной рамкой.
- Pixels/Octant/ASCII отличаются только способом вывода сигнала. Мини-sparkline и полосы
  не получают полную рамку: у них другая задача и подписи/числа рядом.
- Octant: 2×4 прямоугольных субклетки; Canvas эмулирует геометрию, не Unicode-поддержку.
- Sparkline: 8 уровней, каждый ряд масштабируется к своему пику. Не сравнивать абсолютные
  значения разных sparkline по одной высоте! Для абсолютного сравнения нужны единицы/цифры.
- Бары: фиксированная шкала 0–100%, ограниченная ширина до 40 знакомест.

Обновление данных — один sample в секунду; график перерисовывается при новом sample,
смене параметра, палитры или resize. Не держим постоянный 60 FPS цикл ради неподвижной таблицы.
На скрытой вкладке таймер не добавляет данные. Reduced motion запускает макет на паузе.
Нет фиктивного FPS, мощности, температуры или уверенности модели.

## 8. Минимальная будущая интеграция

1. Зафиксировать токены/состояния после просмотра этого архива.
2. Портировать расчёт рядов и сегментов; сравнить выход с `tests/charts.test.cjs`.
3. Выбрать **один** нативный стек под первый продукт. Rust/Ratatui логичен при интеграции
   в Rust-продукт; Go-продукт должен использовать выбранный Go-стек. Ни перенос интерфейса
   ultra-mog, ни обязательный Ratatui не являются частью дизайна SACRA.
4. Разделить данные → состояние → layout → renderer → input. Не смешивать системные
   действия и рисование таблицы. Деструктивные действия требуют отдельного подтверждения.
5. В терминале проверить capability probe, cell size, Unicode width, resize, tmux,
   очистку графических placements и восстановление terminal mode при ошибке.
6. Только затем добавить проверенный native adapter и TUI-навык в общий private kit.

Этот прототип реализует browser/state/layout/chart-часть. Terminal transport, ANSI-парсер,
PTY, реальная системная телеметрия и реальные операции над процессами не реализованы.
